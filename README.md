# 混装短少理赔

称重、拆分、收货与已办款项均为虚构台账。重量单位公斤，金额单位分。

`data` 保存原始记录，`DATA.md` 是资料字典，`recon` 是对账与报表程序，
`output` 是最近一次运行的结果。

## 运行

环境使用 Python 3.11.2。安装锁定的依赖并检查资料：

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
```

生成报表（不访问任何业务系统，只读本地资料）：

```sh
python3 -m recon                      # 结果写到 output/
python3 -m recon --out /tmp/r         # 指定目录
python3 -m recon --as-of 2026-11-14T12:00:00+08:00   # 按当时可见资料重放
python3 -m recon --json               # 同时把 JSON 打到标准输出
```

输出：

| 文件 | 内容 |
| --- | --- |
| `reconciliation.md` | 人读报表：重量区间、赔付款、周结扣款、冲突、关账恒等式 |
| `reconciliation.json` | 同一内容的结构化版本，供后续系统取用 |
| `audit.json` | 每张运单的查账底稿 |
| `audit-<运单>.md` | 单张运单：当时用了哪几张单、哪版合同，现在差多少，下一笔可办 |

## 口径

**称重** 每张磅单的净重是 `毛重 - 皮重`，只在 `±容差` 内成立。修订只替代它
指名的那一版，别的票不受影响；资料按 `reported_at` 截断，可重放当时可见的版本。
同一节点若有多张有效观测，取交集；交集为空是**资料冲突**，不是新增短少。

**物料平衡** 所有投入、合批、拆分、拨出、余货和运输放在同一个平衡里：每个操作
`投入 - 转出 = 申报损耗 + 仍未说明`，并按果园分别成立。报表把三者分列——
正常损耗、转出、仍未说明；只有“仍未说明”可能成为短少。余货、拨出、运输压差
不预先假定责任。

**归属** 合批后的货可能来自多个果园，因此用可行区间而不是点名归属。运单短少
总量有一个区间，每个果园的份额另有一个区间；“能对上某片果园的批号”不等于
“短少都来自那里”。报表给出每个客户、每个果园的**可确认**量与**还不能确认**量，
并对“各客户最大归属量能否同时成立”做联合可行性检查，也给出真实的合计区间
（不是把各单上限相加）。

**买方应赔** 合同版本取首次出运时生效的那一版；免赔量与上限按运单累计，同一
运单的分次申报共用。申报量不是证明量：可赔重量取已确认短少与申报量的较小者，
再减免赔、按公斤金额计、受上限约束。

**果园扣款** 只有能确认到果园的责任量才可扣款。扣款占用该果园**同周的共用货款**，
按责任首次确认的先后顺序扣抵；扣不下的部分留在该单上，不跨周挪用已关账余额。
返还单独成项：已入账的返还才释放后续额度，待付返还什么都不释放；返还从不改写
原扣款或已关账周。

**资料冲突** 新磅单与既有记录不相容时，受影响运单被圈出并暂停新增付款，其余
运单照常结算。冲突本身不计入任何短少；已付现金冻结在账上而不被追回。

**金额分离** 买方应赔与果园扣款分开核算：同一短少在果园间转移只动果园扣款，
确认量变化才动买方余额；两者同时变化时分别列示。历史已付是既成事实，修订只
生成“补付”“追回/待复核”“返还”等新事项，并按复核凭证去重，反复送达不会产生
第二笔。

**关账** 报表按客户、按果园分别汇总，并给出两条可校验的恒等式：
已付 + 下次应付 = 应赔 + 待复核多付；应赔 = 已明确到果园 + 未能分责。
不能分责的客户款、因冲突冻结的已付款、已确认但货款不足的果园责任，都单列在
“挂起事项”，不混进现金总额。

## 数据

原始 CSV 只读；程序不写回 `data`。空值不作为零处理，没有磅单的节点不假定为零。
